# API.md: REIA REST API Specification

Status: Draft v0.1 (Phase 0.5), pending review.
Depends on: PRD.md v0.3, SRS.md v0.1, DATABASE.md v0.2, TAD.md v0.2.
This document defines conventions, authorization, resources and endpoints. The OpenAPI schema generated by the backend is the machine-readable contract, and this document is the human-readable design it must match (section 9).

## 1. Scope and status

- Base path: `/api/v1`. Health endpoints `/healthz` and `/readyz` are at the root.
- The API serves the REIA web frontend. n8n and other integrations use the same API with a scoped credential (deferred).
- Endpoints marked **Reserved** are not part of the MVP.
- Several endpoints depend on tables that are not in DATABASE.md v0.2 yet. They are listed in section 8 and are applied in the DATABASE.md v0.3 revision before Phase 2.

## 2. Conventions

### 2.1 Format

| Item | Rule |
|---|---|
| Content type | `application/json; charset=utf-8`. File imports use `multipart/form-data`. Any other type returns 415 |
| Identifiers | UUID strings |
| Timestamps | ISO 8601 in UTC with `Z`, for example `2026-11-10T09:30:00Z`. Date-only values use `YYYY-MM-DD` |
| Money | Object `{ "amount": "1800000.00", "currency": "AED" }`. The amount is a decimal **string**, never a float. The currency is an ISO 4217 code |
| Area | Object `{ "value": "95.50", "unit": "sqm" }` with unit `sqm` or `sqft` |
| Languages and countries | BCP 47 (`en`, `es`, `pt`, `pt-PT`) and ISO 3166-1 alpha-2 (`AE`, `ES`, `PT`) |
| Field names | `snake_case` |
| Enumerations | Lowercase strings, defined in DATABASE.md |
| Strict requests | Unknown fields in a request body return 422 (`unknown_field`). Clients must ignore unknown fields in responses |
| Null | In `PATCH`, an omitted field is unchanged and an explicit `null` clears a nullable field |

### 2.2 Authentication

- Protected endpoints require `Authorization: Bearer <access_token>`.
- The access token carries the user id and the selected organization id. Role and membership are loaded from the database on every request, so role changes and removals apply immediately.
- The refresh token is an `HttpOnly`, `Secure`, `SameSite=Strict` cookie scoped to `/api/v1/auth`. `POST /auth/refresh` and `POST /auth/logout` also require the header `X-REIA-Client: web` and a same-origin `Origin` header (CSRF protection).
- An endpoint that needs an organization returns 403 `organization_required` when the token has none.

### 2.3 Headers

| Header | Direction | Use |
|---|---|---|
| `X-Request-ID` | request, response | Optional from the client (a UUID). The server generates one if absent and always returns it. It appears in logs and in error bodies |
| `Idempotency-Key` | request | Optional on creating `POST` endpoints (section 2.8) |
| `If-Match` | request | Optional on `PATCH` (section 2.7) |
| `ETag` | response | On single-resource `GET` and on updates |
| `Retry-After` | response | On 429 and 503 |
| `Cache-Control: no-store` | response | On every authenticated response |
| `X-Content-Type-Options: nosniff` | response | On every response |
| `Deprecation`, `Sunset` | response | On deprecated endpoints (section 2.10) |

### 2.4 Pagination

Lists use cursor pagination.

Request: `?limit=25&cursor=<opaque>`. The default `limit` is 25 and the maximum is 100 (proposed, TAD section 21).

```json
{
  "items": [],
  "page": { "limit": 25, "next_cursor": "eyJpZCI6Ij...", "has_more": true }
}
```

The cursor is opaque, signed and tied to the filters and the sort order it was issued for. A cursor reused with different filters returns 400 `invalid_cursor`. Ordering is deterministic (a sort key plus the id).

### 2.5 Filtering and sorting

Filters are explicit query parameters per endpoint. Array filters repeat the parameter (`status=open&status=in_progress`). `sort` accepts a whitelist per endpoint, with a leading `-` for descending. Range filters use `from` (inclusive) and `to` (exclusive).

**Privacy rule for query strings:** personal data (names, phone numbers, search text) in URLs can end up in access logs. Free-text search with content therefore uses `POST /search`. The customer name filter `q` is allowed on `GET /customers`, and access logs at the proxy and the application must not record query strings (SECURITY.md, DEPLOYMENT.md).

### 2.6 Updates

`PATCH` is a partial update. State changes (task status, draft status, fact lifecycle, conversation linking) use explicit action endpoints (`POST /tasks/{id}/complete`) so that every transition is validated against the state models in SRS section 6. An invalid transition returns 409 `invalid_state_transition`.

### 2.7 Optimistic concurrency

Single-resource responses include a weak `ETag` derived from the resource id and `updated_at`. A `PATCH` or action request may send `If-Match`. A mismatch returns 412 `precondition_failed`. Without `If-Match` the update is applied.

### 2.8 Idempotency

Creating `POST` endpoints accept `Idempotency-Key` (a UUID recommended, up to 64 characters). The server records the key with the user, the route and a hash of the request body for 24 hours.
- Same key, same body: the server returns the original result (it replays by returning the current resource, with the same status code and the header `Idempotent-Replayed: true`).
- Same key, different body: 422 `idempotency_key_reuse`.
- Conversation imports are additionally idempotent by content hash (section 6.5).

### 2.9 Rate limiting

Limits are per user and per IP and are proposed starting values (TAD section 21). A limited request returns 429 `rate_limited` with `Retry-After`.

| Group | Proposed limit |
|---|---|
| Login, registration, password reset, verification | 5 failed or repeated attempts per 15 minutes per account and per IP, then increasing delay |
| Interactive AI endpoints (assistant, drafts, briefings, translations, semantic search) | 20 per user per minute, plus the organization cost limit (`ai_quota_exceeded`) |
| Everything else | 120 per user per minute |

### 2.10 Versioning

The major version is in the path. Additive changes (new optional fields, new endpoints, new enumeration values documented as extensible) do not change the version. Removing or changing a field, changing semantics or tightening validation requires `/v2`. A deprecated endpoint sends `Deprecation` and `Sunset` headers for at least one release cycle.

### 2.11 Localization

Error `message` text is localized to the user's UI language (or `Accept-Language` when unauthenticated). Error `code` values are stable and are what clients must branch on. AI output language is controlled by the `language` field of the AI endpoints and defaults to the user's UI language.

### 2.12 Security conventions

- All traffic uses TLS. CORS allows only configured origins (the frontend is same-origin in production).
- Resources of another organization return 404 `not_found`, never 403, so existence is not revealed.
- Customers a member cannot see (assigned to someone else) also return 404.
- No endpoint returns password hashes, token hashes, encrypted credentials or provider keys.
- Requests that would delete data permanently are not available on the API, except through the erasure process (section 6.14).

## 3. Error model

### 3.1 Envelope

```json
{
  "error": {
    "code": "validation_error",
    "message": "The request is not valid.",
    "details": [
      { "field": "identifiers[0].value", "code": "invalid_phone", "message": "Enter a valid phone number." }
    ],
    "request_id": "9b3a6a5e-2c58-4d0a-8d0f-2b8f6c0c4f11"
  }
}
```

`details` is present for validation errors and some conflicts. It never echoes sensitive values.

### 3.2 Catalog

| HTTP | Code | Meaning |
|---|---|---|
| 400 | `bad_request`, `invalid_cursor`, `invalid_filter` | Malformed request |
| 401 | `authentication_required`, `invalid_credentials`, `token_expired`, `token_invalid`, `refresh_token_reuse` | Authentication problems. `refresh_token_reuse` also revokes the session family |
| 403 | `permission_denied`, `organization_required`, `email_not_verified`, `account_suspended`, `policy_blocked`, `organization_terminated` | Not allowed |
| 404 | `not_found` | Missing, or not visible to the caller |
| 405 | `method_not_allowed` | For example `DELETE /conversations/{id}` |
| 409 | `duplicate_identifier`, `already_processing`, `invalid_state_transition`, `sole_owner`, `duplicate_membership`, `conflict`, `legal_hold_active` | State conflicts |
| 412 | `precondition_failed` | `If-Match` mismatch |
| 413 | `payload_too_large` | Over the import size limit |
| 415 | `unsupported_media_type` | |
| 422 | `validation_error`, `unknown_field`, `unsupported_encoding`, `unsupported_format`, `idempotency_key_reuse`, `policy_violation` | Valid syntax, invalid content. `policy_violation` is returned when a provider setting would widen what code or deployment allows |
| 429 | `rate_limited`, `ai_quota_exceeded` | |
| 500 | `internal_error` | Generic. Details only in logs |
| 502 | `ai_output_invalid` | Model output failed validation after the retry |
| 503 | `ai_provider_unavailable`, `service_unavailable` | |

## 4. Permissions

Each endpoint lists a permission code. The mapping to roles follows SRS section 3. "Visible" means all customers for owners and admins and assigned customers for agents and read-only members.

| Code | Owner | Admin | Agent | Read-only |
|---|---|---|---|---|
| `account.self` | Yes | Yes | Yes | Yes |
| `org.read` | Yes | Yes | Yes | Yes |
| `org.manage` | Yes | Yes | No | No |
| `org.terminate`, `org.export`, `ai_settings.manage`, `legal_hold.manage` | Yes | No | No | No |
| `members.manage`, `audit.read` | Yes | Yes | No | No |
| `customer.create` | Yes | Yes | Yes | No |
| `customer.read` | Visible | Visible | Visible | Visible |
| `customer.write`, `ai.use`, `task.manage`, `consent.manage` | Visible | Visible | Visible | No |
| `customer.assign`, `customer.merge`, `customer.export`, `customer.erase` | Yes | Yes | No | No |
| `voice_profile.manage` | Own | Own | Own | No |
| `dashboard.read`, `search.use` | Visible | Visible | Visible | Visible |

Admins cannot change or remove owners. A task, draft or briefing inherits the visibility of its customer.

## 5. Shared schemas

### 5.1 Basic types

```text
Money        { amount: string, currency: string }
Area         { value: string, unit: "sqm" | "sqft" }
Location     { country?, region?, city?, neighborhood?, development?, postal_code? }
Page         { limit: int, next_cursor: string | null, has_more: bool }
```

### 5.2 FactValue (discriminated by `value_type`)

| `value_type` | Shape |
|---|---|
| `text` | `{ "value_type": "text", "text": "Prefers a quiet building" }` |
| `money` | `{ "value_type": "money", "min": "1500000.00", "max": null, "currency": "AED" }` |
| `area` | `{ "value_type": "area", "min": "90", "max": "120", "unit": "sqm" }` |
| `integer` | `{ "value_type": "integer", "min": 2, "max": 3 }` |
| `boolean` | `{ "value_type": "boolean", "value": true }` |
| `date` | `{ "value_type": "date", "value": "2027-03-01" }` |
| `location` | `{ "value_type": "location", "location": { "country": "AE", "city": "Dubai", "neighborhood": "Dubai Marina" } }` |
| `json` | `{ "value_type": "json", "data": { } }` |

A `money` value always needs `currency`. An `area` value always needs `unit`. The fact key registry defines which `value_type` a key accepts (`GET /reference/fact-keys`).

### 5.3 SourceRef

```json
{
  "type": "message",
  "id": "5d2a9c1e-0b7f-4e53-8a7d-3c9e1f6b2a40",
  "conversation_id": "a4b1c7d2-92e3-4f65-b0a1-6d8e2f4c9b13",
  "date": "2026-10-02T14:05:00Z",
  "language": "en",
  "quote": "My budget is now around 1.8 million dirhams.",
  "lifecycle_status": null,
  "verification_status": null
}
```

`type` is `fact`, `message`, `event`, `commitment` or `summary`. `quote` is present for messages and facts and is in the original language. `lifecycle_status` and `verification_status` are present for facts.

## 6. Endpoints

Success codes: `GET` 200, create 201, accepted asynchronous work 202, no content 204.

### 6.1 Authentication (`/auth`)

| Method | Path | Permission | Success | Notes |
|---|---|---|---|---|
| POST | `/auth/register` | public | 202 | Body `email`, `password`, `full_name`, `ui_language?`. Always returns 202 `{ "message_code": "verification_sent" }`, whether or not the email exists |
| POST | `/auth/verify-email` | public | 204 | Body `token`. Also confirms an email change |
| POST | `/auth/resend-verification` | public | 202 | Body `email`. Always 202 |
| POST | `/auth/login` | public | 200 | See example. 401 `invalid_credentials`. 403 `email_not_verified` only after a correct password |
| POST | `/auth/refresh` | cookie | 200 | Rotates the refresh token. 401 `refresh_token_reuse` revokes the family |
| POST | `/auth/logout` | cookie | 204 | Revokes the session family, clears the cookie |
| POST | `/auth/switch-organization` | `account.self` | 200 | Body `organization_id`. Requires active membership. Returns a new access token |
| POST | `/auth/forgot-password` | public | 202 | Body `email`. Always 202 |
| POST | `/auth/reset-password` | public | 204 | Body `token`, `new_password`. Revokes all sessions |
| POST | `/auth/change-password` | `account.self` | 204 | Body `current_password`, `new_password`. Revokes the other sessions |

Login request and response:

```json
{ "email": "agent@example.com", "password": "correct horse battery staple", "organization_id": null }
```

```json
{
  "access_token": "eyJhbGciOi...",
  "token_type": "bearer",
  "expires_in": 900,
  "user": { "id": "0e3f5a52-6c4b-4b57-9d0c-18f1a0b9d7c2", "email": "agent@example.com", "full_name": "Sara Khan", "ui_language": "en" },
```

## 7. Asynchronous operations

Work that calls AI providers in the background returns a `Job` and does not block.

1. `POST /conversations` returns 201 with `processing_status: "pending"` and a `job`.
2. The client polls `GET /conversations/{id}` (or `GET /jobs/{id}`) until `processing_status` is `processed` or `failed`. A notification is also created when processing finishes.
3. On `failed`, `processing_error_code` explains the category (for example `provider_unavailable`, `output_invalid`, `policy_blocked`) without any message content. `POST /conversations/{id}/process` retries.

Interactive AI endpoints (assistant, drafts, briefings, translations) are synchronous and have their own latency budget. Their errors are 502 and 503 as listed in section 3.2. Server-sent events for live updates are deferred.

## 9. Contract governance and testing

- The backend generates the OpenAPI schema. CI exports it and compares it with the committed `docs/openapi.json` to detect breaking changes. A breaking diff fails the build unless the version changes.
- The frontend types are generated from that schema.
- Every route declares its permission code. A test enumerates all routes and fails if one has none (TAD 7.3).
- Contract tests cover: the error envelope on every error path, pagination cursor rules, idempotent replay, `If-Match` behavior, state-transition errors, 404 for another tenant and for invisible customers, and 405 on `DELETE` and `PUT` for conversations.
- The test suite includes the privacy rules: no personal data in access logs, no query strings logged, no content in error bodies.
- Interactive documentation (Swagger UI) is disabled in production.
